# 原生车库控制：配置、迁移和验收清单

版本：**v0.8.1**（V1 + hold_open / after_exit），沿用现有配置，无新增参数。短暂机器人观测缺样限时重采样，故障/人工保持也不跳过返航暂停；未取得自动开门/恢复授权时只制动。旧门请求未结束前不能重置或发起新门动作。新控制仍默认关闭；启用后中途回洗/补电不收尾，最终确认结束并稳定停靠后关门。v0.8.0 收窄外部命令判据（空闲且门静止时不锁存），新增 `request_garage_open`，并把锁存事件升级为可通知的 `previous_phase` 版本。v0.8.1 修正离库判定：位置读不到不清武装、已出区时人工关门不锁存。物理验收由用户完成。

## 1. 配置：核实门实际怎样反馈

“标定”就是把实际门位、传感器读数和时间对上。已有可靠实测值可沿用；缺失值由用户测量，助手不操作设备。
首页顶部勾选“继续配置单机车库控制”后提交，再选择本条目的 V1 扫地机；本页改动在车库流程最后与车库设置一起保存。不继续配置车库时，本页提交即保存。
“旧版兼容设置”分组及旧“柜门保护”“柜门实体”字段已移出界面；已有存储值保留，不自动停用旧保护，门/机器人流程和已有绑定不自动改动。运行监测数值正常预填；提交实际缺项或无效数字时，顶部中文提示列出具体字段名，已填内容保留。
新版按“基本/来源 → 所选反馈 → 相关时长/交接”填写；未选来源不用填，不猜实际行程或到位极性。
v0.7.2 会预填缺失辅助项：余量10秒、触点稳定1秒、位置稳定2秒、停靠稳定5秒，超时初值至少90秒并参考已知行程；旧值保留，真实行程和两个确认框仍须用户核实。使用v0.7.1时可手工填写这些建议值。

| 项目 | 记录什么 |
| --- | --- |
| 控制目标 | 实际负责开关这扇门的 `cover` 实体 |
| 全开/全闭反馈 | 两个方向分别选端点传感器、位置或计时；没有全闭反馈不代表已经全开 |
| 端点极性 | 门实际到达该端点时，所选传感器是 `on` 还是 `off`；例如全闭到位也可能报 `off` |
| 位置性质/阈值 | `current_position` 是真实测量还是估算/目标回声；核实什么数值才足够通行/闭合，不能一律照搬 95/5 |
| 完整行程 | 全闭→全开的秒数、全开→全闭的秒数；分别填写，不默认相等 |
| 等待参数 | 辅助项可从上述建议值开始；超时须大于所选来源最长等待。例：计时开门35秒+余量10秒，需要超时>45秒，可填90秒 |

没有可靠反馈的方向可明确选 `timed`，须接受估算风险；计时不能证明门没卡住，也不会显示为“已确认到位”。

`timed` 或 `position` + `estimated` 的反馈恢复后，旧等待作废；新显式请求重新等待该方向完整行程+余量，例如本门35+10=45秒，不是通用默认值。已锁存的故障（fault）/人工保持（manual_hold）不自动清除；`reset_garage_control` 只复核、不发设备命令。活动任务复核后仍无通行许可时保持 `manual_hold`，等待用户明确请求 `resume_task`，再重新开门计时并保留原会话 sid。

## 2. 迁移：交接同一扇门的控制权

- [ ] 备份现有 HA 配置；新车库控制先保持关闭，保存按机器人绑定的草稿。
- [ ] 对照 HA 实际配置核对旧主动门控：仓库中的 **Roborock Garage Door State Machine**（`automation.roborock_garage_door_statemachine`）及其 `*_plus` 前身；交接时由用户停用，不能与新控制器双控。
- [ ] “无人自动关门”等家庭策略改为请求 `roborock_plus.request_garage_close`，不直接关闭 cover；占用条件可接“允许关门”实体。
- [ ] 清扫日程、房间选择、通知按用途保留；`vacuum_garage_door_auto_unlock` 等释放离合流程需单独核对可靠停稳条件，不能按名字批量停用/删除。
- [ ] 旧解锁自动化保持原样；可信全闭、静止且没有未结束操作时，`cover.stop_cover` 只释放离合，保留原故障/人工保持。手动或电动开门能力不受限制；集成后续自动流程仍须满足原有授权。
- [ ] 确认没有正在清扫或待续任务、机器人安全停靠，完成标定后再由用户确认交接并启用；首次初始化仍须稳定观测，不会因勾选确认立即放行。

以上名称来自仓库，**不代表已确认你家 HA 当前启用情况**。[旧方案清单](../automations/README.md#四个自动化)

## 3. 验收：记录看到的结果

实物动作仅用户操作；失联、并发等故障场景优先用隔离仿真，不由助手启动扫地机或开关门。

- [ ] 开始/例程：门先达到通行条件，机器人随后启动；失败只报告，不自动补偿关门。
- [ ] 隔离回放：全闭解锁命令确实执行，随后显式清扫仍先完整开门；蓝图失败后能按窗口重试，窗口结束只发一次最终告警。更新集成不会自动更新 HA 已导入的蓝图，部署时需另外更新。
- [ ] 空闲时的外部开门不锁存（v0.8.0）：控制器 `phase=idle`、无任务、门已静止时，从界面或自动化开门后 `garage_problem` 应保持 `off`，随后触发的清扫应被接受，而不是报 `manual_override`。
- [ ] 任务中的外部开门仍锁存（v0.8.0）：清扫过程中从界面开门，`garage_problem` 应变 `on`、`phase=manual_hold`，并收到一条「柜门控制已接管」告警。
- [ ] 折叠门联动走受控通道（v0.8.0）：折叠门打开时日志里应出现集成发出的 `open_cover`，约 45 秒后 `garage_passage_allowed` 变 `on`；已经可通行时不应重复驱动门。
- [ ] after_exit：出库无额外暂停，确认区外后关门；返航必须确认暂停、确认门全开，再继续同一返航；再次离库可再次关门。
- [ ] 出区后自动关门（v0.8.1）：机器人清扫中离开危险区后，日志里应出现**集成发出的** `close_cover`（不是等你手动关）。判定看 `garage_closed_confirmed` 变 on，且中间 `outside_danger_zone` 出现过 `unknown` 也不影响关门。
- [ ] 清扫中手动关门不锁死下次（v0.8.1）：机器人已在区外时你手动关门，`garage_problem` 应保持 `off`（会收到 `external_close_after_exit` 事件），随后触发的清扫应被接受。机器人在区内时手动关门仍应变 `manual_hold`。
- [ ] 隔离故障回放：故障、人工保持、取消或未知任务仍先确认返航暂停，只制动、不自动开门/恢复；恢复记录不能清除旧故障。
- [ ] 隔离缺样回放：关闭中缺样先停止并等重采样，无停止能力则反向打开自己的关闭动作；门已关时限时观察，持续失败报错，未知不授权关门。
- [ ] 隔离并发回放：慢速旧门请求不挡住返航暂停；安全暂停完成但旧门请求未结束时，重置仍须拒绝，旧请求退出后才允许显式重置。
- [ ] 中途回洗/补电/继续：仍属同一任务，门保持开，不提前收尾。
- [ ] 最终回库：本次任务确实结束、稳定停靠、基站位置自洽且家庭许可允许后，才关闭并验证门位。
- [ ] 家庭禁关时不关闭，但不妨碍明确请求开门；反馈失联/人工保持时阻止后续危险动作，故障可见，恢复反馈不自动解除阻塞。
- [ ] 重启：不重放移动命令；未知外部任务导致旧关联失效，reset 不能清空它或复活旧导航授权。
