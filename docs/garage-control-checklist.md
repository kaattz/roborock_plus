# 原生车库控制：配置、迁移和验收清单

版本以本页所在 Git 提交为准；当前为待现场验收的候选版本。支持 **V1 + hold_open**：整场任务保持门开，中途回洗/补电不关门，最终确认结束并稳定停靠后关门。`after_exit` 尚未开放。

## 1. 配置：核实门实际怎样反馈

“标定”就是把实际门位、传感器读数和时间对上。已有可靠实测值可沿用；缺失值由用户测量，助手不操作设备。

| 项目 | 记录什么 |
| --- | --- |
| 控制目标 | 实际负责开关这扇门的 `cover` 实体 |
| 全开/全闭反馈 | 两个方向分别选端点传感器、位置或计时；没有全闭反馈不代表已经全开 |
| 端点极性 | 门实际到达该端点时，所选传感器是 `on` 还是 `off`；例如全闭到位也可能报 `off` |
| 位置性质/阈值 | `current_position` 是真实测量还是估算/目标回声；核实什么数值才足够通行/闭合，不能一律照搬 95/5 |
| 完整行程 | 全闭→全开的秒数、全开→全闭的秒数；分别填写，不默认相等 |
| 等待参数 | 行程余量、反馈稳定时间、停靠稳定时间；动作超时大于最长行程+余量+反馈稳定时间 |

没有可靠反馈的方向可明确选 `timed`，须接受估算风险；计时不能证明门没卡住，也不会显示为“已确认到位”。

## 2. 迁移：交接同一扇门的控制权

- [ ] 备份现有 HA 配置；新车库控制先保持关闭，保存按机器人绑定的草稿。
- [ ] 对照 HA 实际配置核对旧主动门控：仓库中的 **Roborock Garage Door State Machine**（`automation.roborock_garage_door_statemachine`）及其 `*_plus` 前身；交接时由用户停用，不能与新控制器双控。
- [ ] “无人自动关门”等家庭策略改为请求 `roborock_plus.request_garage_close`，不直接关闭 cover；占用条件可接“允许关门”实体。
- [ ] 清扫日程、房间选择、通知按用途保留；`vacuum_garage_door_auto_unlock` 等释放离合流程需单独核对可靠停稳条件，不能按名字批量停用/删除。
- [ ] 确认没有正在清扫或待续任务、机器人安全停靠，完成标定后再由用户确认交接并启用；首次初始化仍须稳定观测，不会因勾选确认立即放行。

以上名称来自仓库，**不代表已确认你家 HA 当前启用情况**。[旧方案清单](../automations/README.md#四个自动化)

## 3. 验收：记录看到的结果

实物动作仅用户操作；失联、并发等故障场景优先用隔离仿真，不由助手启动扫地机或开关门。

- [ ] 开始/例程：门先达到通行条件，机器人随后启动；失败只报告，不自动补偿关门。
- [ ] 中途回洗/补电/继续：仍属同一任务，门保持开，不提前收尾。
- [ ] 最终回库：本次任务确实结束、稳定停靠、基站位置自洽且家庭许可允许后，才关闭并验证门位。
- [ ] 家庭禁关时不关闭，但不妨碍明确请求开门；反馈失联/人工保持时阻止后续危险动作，故障可见，恢复反馈不自动解除阻塞。
- [ ] 重启：不重放移动命令；未知外部任务导致旧关联失效，reset 不能清空它或复活旧导航授权。
